## Optimization phase (GA / PSO / ACO / random vs baselines)
16. Optimizers written from scratch (numpy), not mealpy. One shared [0,1] encoding (39 feature entries, >0.5 = kept, min 5 = top-5 values, then hyperparameters) so all methods are comparable and no dependency is added.
17. Fitness = macro F1 on a fixed 50k stratified validation subsample for a model trained on a fixed 100k stratified training subsample (>=200 rare-class rows kept) minus 0.001*fraction of features. optimization/core.py reads train/val rows only. MLP early stopping uses a 10% hold-out of the training subsample, not the fitness validation set.
18. Population/swarm/ant count 20 for all (ACOR archive size 20, q=0.2, xi=0.85; GA: tournament 3, BLX-0.5, p_c 0.9, Gaussian mutation p=0.1 sigma 0.15, elitism 2; PSO: w 0.72, c1=c2=1.49, vmax 0.25). Same seed and same initial 20 candidates for all four methods. One search seed per method (time); seed noise is estimated through retraining final configs with seeds 42/43/44.
19. Budget = number of UNIQUE evaluations (cache hits free, logged as n_calls). Each (model, task) has the same budget for all 4 methods. Timing probe (6 random candidates, 4 concurrent workers x 4 threads, the real run conditions): mean s/eval dt 0.5/1.1, rf 4.5/6.6, xgb 1.05/8.6, mlp 9.8/10.1 (binary/multi). Four methods run concurrently per combo, combos sequentially; budget chosen so wall time is about 8-10 h total: dt 800, rf_binary 800, xgb_binary 800, mlp_binary 600, rf_multi 800, xgb_multi 650, mlp_multi 580 (cheap models capped at 800 evals, leftover time given to expensive ones). Resource cost per run is recorded as process CPU seconds (wall time includes contention).
20. Final models: winner = best fitness of the run; retrain on the full training split (MLP early stopping on full validation split like the baseline), scored once on test. Seeds 43/44 retrains are separate models (ids *_s43, *_s44), each scored once per model id, so each winner configuration touches test three times; selection never used those scores.
21. binary_rf_pso used 689 of its 800 unique evaluations: the swarm collapsed onto already-evaluated candidates and the 100 x budget call guard stopped it. Kept as is (it is how PSO behaved), disclosed in REPORT.md; verify.py accepts a short run only when the guard triggered.
22. The iot-bench Docker image had disappeared and the first rebuild failed because Docker Desktop crashed under memory pressure from the parallel optimizer runs; rebuilt after the runs finished. Memory pressure also stopped background monitors, so heavy steps are run one at a time.
23. Budgets were not reduced afterwards, so the comparison stays equal. Total process CPU time 127.6 h.
